1.1 题目名称

掌上约球——校园球友召集平台

1.2 主要功能

本项目为一个面向校园和社区的球友召集平台移动Web应用，主要功能如下：

【用户系统】
- 用户注册（账号密码、手机号、常住地、球类兴趣）
- 用户登录（JWT token 认证）
- 个人信息管理（头像上传、资料编辑、密码修改、退出登录）

【邀约功能】
- 发起邀约（选择球类、时间、地点、人数，支持高德地图选点）
- 管理邀约状态（等待中/已召集/已终止）

第2章 项目背景与需求

================================================================================

2.1 背景与意义

随着高校体育运动的普及，越来越多的大学生希望在课余时间参与球类运动。然而，在实际组织运动的过程中，学生们往往面临"想打球却找不到人"的困境。传统的组织方式主要依赖微信群聊或朋友圈发布信息，这种方式存在明显不足：信息容易被其他消息淹没，无法按照地理位置匹配附近的球友，也缺乏对邀约状态的有效管理。

本项目"掌上约球"正是为了解决这一痛点而设计的。它的核心价值在于让用户能够快速找到附近想打球的人，通过发起邀约和加入邀约的方式，高效地凑齐运动人数。与传统方式相比，本平台具有基于地理位置的智能匹配、邀约状态的自动管理、参与人信息的规范展示等优势，能够显著提升校园球类运动的组织效率。

2.2 功能需求

从用户使用场景出发，本系统需要满足以下核心需求：用户打开应用后，首页即可看到附近正在召集中的球局列表，列表按照距离从近到远排列，也可以按时间排序或按球类筛选。用户看到感兴趣的邀约后，点击即可查看详情并一键加入，当参与人数达到上限时系统自动将邀约标记为"已召集"状态。同时，用户也可以自己发起一次邀约，选择球类、时间、地点和所需人数，提交后等待其他球友加入。发起人可以随时查看当前参与人的信息，也可以主动终止或删除邀约。此外，系统还提供完整的个人信息管理功能，包括头像上传、资料编辑和密码修改等。

3.2.2 前端核心代码

【F1: Axios 封装与 JWT Token 自动注入】

前端通过封装Axios实例来统一管理所有HTTP请求。在请求拦截器中，每次发送请求前会自动从localStorage中读取JWT token，并将其添加到请求头的Authorization字段中，格式为"Bearer token"。这样所有需要认证的API请求都会自动携带身份凭证，无需在每个接口调用处手动处理。在响应拦截器中，统一处理错误情况：当收到401状态码时，说明token已过期或无效，此时自动清除本地存储的token并跳转到登录页面，提示用户重新登录；对于其他错误则通过Toast组件展示错误信息。

```javascript
// frontend/src/api/request.js — Axios封装+JWT注入+401自动跳转
import axios from 'axios'
import { showToast } from 'vant'
import router from '@/router'

const request = axios.create({
  baseURL: '/api/v1',
  timeout: 10000
})

// 请求拦截器：注入 token
request.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器：统一错误处理
request.interceptors.response.use(
  response => response.data,
  error => {
    if (error.response?.status === 401) {
      localStorage.removeItem('token')
      router.push('/login')
      showToast('登录已过期，请重新登录')
    } else {
      showToast(error.response?.data?.message || '网络错误')
    }
    return Promise.reject(error)
  }
)

export default request
```

【F3: 路由导航守卫】

前端路由使用Vue Router的全局前置守卫beforeEach来实现页面访问控制。每个路由配置中通过meta字段标记该页面是否需要登录（auth: true）或仅限未登录用户访问（guest: true）。守卫逻辑为：当用户访问需要认证的页面时，检查localStorage中是否存在token，如果不存在则自动重定向到登录页；当已登录用户访问登录或注册页面时，自动重定向到首页，避免重复登录。

```javascript
// frontend/src/router/index.js — 导航守卫
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('token')
  if (to.meta.auth && !token) {
    next('/login')
  } else if (to.meta.guest && token) {
    next('/')
  } else {
    next()
  }
})
```

3.3.1 邀约状态流转图

邀约在其生命周期中存在四种状态：等待中（waiting）、已召集（gathered）、已终止（terminated）和已过期（expired）。其中前三种状态存储在数据库中，已过期状态不存储，而是在查询时根据活动时间是否已过动态计算得出。状态流转规则如下：邀约创建后默认为等待中状态；当参与人数达到设定上限时自动流转为已召集状态；如果有人退出导致人数不足，则从已召集恢复为等待中；发起人可以主动终止处于等待中的邀约；终止后的邀约可以被发起人删除（软删除）。

3.3.2 后端核心代码

【B1: JWT Token 签发与解析】

后端使用golang-jwt库实现JWT token的签发和解析。签发时，将用户ID和过期时间作为Claims载荷，使用HS256对称加密算法和预配置的密钥进行签名，生成token字符串返回给前端。token有效期设置为7天，在课程项目场景下无需实现刷新token机制。解析时，使用相同的密钥验证token签名的完整性和有效期，验证通过后从Claims中提取用户ID返回，供后续业务逻辑使用。

```go
// backend/utils/jwt.go — JWT token签发与解析
package utils

import (
    "time"
    "github.com/golang-jwt/jwt/v5"
    "ballmate/config"
)

// GenerateToken 签发 JWT token
func GenerateToken(userID uint) (string, error) {
    claims := jwt.MapClaims{
        "user_id": userID,
        "exp":     time.Now().Add(config.TokenExpiry).Unix(),
    }
    token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
    return token.SignedString([]byte(config.JWTSecret))
}

// ParseToken 解析 JWT token，返回 userID
func ParseToken(tokenString string) (uint, error) {
    token, err := jwt.Parse(tokenString, func(token *jwt.Token) (interface{}, error) {
        return []byte(config.JWTSecret), nil
    })
    if err != nil {
        return 0, err
    }
    claims, ok := token.Claims.(jwt.MapClaims)
    if !ok || !token.Valid {
        return 0, jwt.ErrTokenInvalidClaims
    }
    userID := uint(claims["user_id"].(float64))
    return userID, nil
}
```

【B2: JWT 认证中间件】

认证中间件是保护API接口安全的核心组件。它作为Gin的中间件函数注册在需要认证的路由组上，在请求到达实际处理函数之前执行身份验证。具体流程为：首先从HTTP请求头中获取Authorization字段，如果该字段为空则直接返回401未授权错误；然后去除"Bearer "前缀提取token字符串，调用ParseToken函数验证token的签名和有效期；验证通过后将解析出的用户ID存入Gin的上下文（Context）中，后续的Handler函数可以通过c.GetUint("userID")获取当前登录用户的ID，从而实现基于用户身份的业务逻辑。

```go
// backend/middleware/auth.go — JWT认证中间件
package middleware

import (
    "net/http"
    "strings"
    "github.com/gin-gonic/gin"
    "ballmate/utils"
)

// AuthMiddleware JWT 认证中间件
func AuthMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        authHeader := c.GetHeader("Authorization")
        if authHeader == "" {
            c.JSON(http.StatusUnauthorized, gin.H{"code": -1, "message": "未登录"})
            c.Abort()
            return
        }
        tokenString := strings.TrimPrefix(authHeader, "Bearer ")
        if tokenString == authHeader {
            c.JSON(http.StatusUnauthorized, gin.H{"code": -1, "message": "token格式错误"})
            c.Abort()
            return
        }
        userID, err := utils.ParseToken(tokenString)
        if err != nil {
            c.JSON(http.StatusUnauthorized, gin.H{"code": -1, "message": "token无效或已过期"})
            c.Abort()
            return
        }
        c.Set("userID", userID)
        c.Next()
    }
}
```

【B3: Haversine 距离计算】

附近约球功能的核心是根据用户当前位置计算每条邀约与用户之间的地理距离。本项目使用Haversine公式来计算地球表面两点之间的球面距离。该公式将两点的经纬度坐标转换为弧度，然后通过三角函数计算出两点间的圆心角，最后乘以地球半径（约6371公里）得到实际距离。由于SQLite数据库不支持MySQL中的RADIANS等数学函数，本项目在SQL查询中使用手动的pi/180转换来替代，同时在Go层实现了一个回退方案：当SQLite的数学扩展不可用时，先查询出所有符合条件的邀约，然后在内存中使用Go的math包计算距离并排序。

```go
// backend/service/invitation.go — Haversine距离计算
const earthRadiusKm = 6371.0

// haversineDistance 计算两点间球面距离（公里）
func haversineDistance(lat1, lng1, lat2, lng2 float64) float64 {
    dLat := (lat2 - lat1) * math.Pi / 180
    dLng := (lng2 - lng1) * math.Pi / 180
    lat1Rad := lat1 * math.Pi / 180
    lat2Rad := lat2 * math.Pi / 180

    a := math.Sin(dLat/2)*math.Sin(dLat/2) +
        math.Cos(lat1Rad)*math.Cos(lat2Rad)*
            math.Sin(dLng/2)*math.Sin(dLng/2)
    c := 2 * math.Atan2(math.Sqrt(a), math.Sqrt(1-a))
    return earthRadiusKm * c
}
```

【B4: 加入邀约 + 事务保证 + 自动状态流转】

加入邀约是系统中逻辑最复杂的操作之一，需要处理多种校验和并发安全问题。首先校验邀约是否存在以及当前状态是否为等待中（通过computeStatus动态计算，确保已过期的邀约也无法加入）。然后使用数据库事务来保证容量检查和插入操作的原子性：在事务内先查询当前参与人数，如果已满则返回错误；未满则插入参与记录，如果违反唯一索引约束说明用户已经加入过。插入成功后重新查询参与人数，如果达到上限则自动将邀约状态更新为gathered。整个过程在一个事务中完成，避免了并发场景下多人同时加入导致超员的问题。

```go
// backend/service/invitation.go — 加入邀约+事务+状态流转
// JoinInvitation 加入邀约
// 校验：邀约存在、状态为waiting、未满员、未重复加入
// 加入后若满员则自动将状态流转为gathered
func JoinInvitation(invitationID, userID uint) error {
    var inv model.Invitation
    if err := DB.First(&inv, invitationID).Error; err != nil {
        return errors.New("邀约不存在")
    }
    if computeStatus(inv) != "waiting" {
        return errors.New("该邀约已无法加入")
    }
    // 事务保证容量检查和插入的原子性，防止并发超员
    return DB.Transaction(func(tx *gorm.DB) error {
        var count int64
        tx.Model(&model.Participation{}).
            Where("invitation_id = ? AND deleted_at IS NULL", invitationID).Count(&count)
        if int(count) >= inv.MaxPeople {
            return errors.New("邀约人数已满")
        }
        if err := tx.Create(&model.Participation{
            InvitationID: invitationID, UserID: userID,
        }).Error; err != nil {
            return errors.New("您已加入该邀约")
        }
        var newCount int64
        tx.Model(&model.Participation{}).
            Where("invitation_id = ? AND deleted_at IS NULL", invitationID).Count(&newCount)
        if int(newCount) >= inv.MaxPeople {
            tx.Model(&inv).Update("status", "gathered")
        }
        return nil
    })
}
```

5.2 不足与展望

本项目目前仍存在一些可以改进的方面。在实时性方面，当前用户需要手动刷新页面才能看到邀约状态的变化（如有人加入或退出），未来可以引入WebSocket技术实现服务端主动推送，让用户实时收到邀约状态变更通知。在社交功能方面，可以增加球友关注、运动评价、聊天等社交互动功能，增强用户粘性。在性能优化方面，当邀约数据量较大时，基于Haversine公式的全表扫描效率较低，未来可以引入空间索引（如R-Tree）或GeoHash方案来提升距离查询性能。在部署形态方面，当前为移动端H5应用，未来可以考虑使用uni-app或Flutter将其转为原生移动应用，获得更好的系统级能力（如后台推送通知、离线缓存等）。
